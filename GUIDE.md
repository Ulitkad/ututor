# uTutor

Закрытая веб-платформа для репетиторов русского языка: библиотека заданий,
учебные профили учеников и групп, интерактивные тренировки с сохранением прогресса.

## Стек

- FastAPI, SQLAlchemy 2, Pydantic 2, SQLite с внешними ключами и WAL.
- Vue 3, Composition API, Vue Router, Pinia, Vite, Tailwind CSS 4, Lucide.
- JWT access-токен в памяти приложения; ротируемый refresh-токен в HttpOnly,
  SameSite=Strict cookie. Пароли хешируются Argon2. Access живёт 15 минут,
  refresh — 30 дней. Сброс пароля отзывает все сессии аккаунта.
- Изолированная база заданий и профили для каждого преподавателя.
  Администратор управляет аккаунтами и собственными материалами.

## Запуск в Docker

Требуются Docker Engine, Docker Compose v2 и OpenSSL. Из корня репозитория:

```sh
sh deploy/init.sh
docker compose up --build -d
curl --fail http://localhost:8080/api/health
cat .admin_credentials
```

`deploy/init.sh` создаёт `.env` с криптографически случайным JWT-секретом,
каталог `data/` и пустой файл `.admin_credentials`. Уже существующие файлы
не перезаписываются. Файл учётных данных нужно создать **до** Compose,
чтобы Docker не создал вместо него каталог.

При первом запуске, если в БД нет пользователей, сервер создаёт `admin`
с Base64-паролем из 32 символов и записывает его в `.admin_credentials`
**в корне проекта на хосте** через bind mount. Права файла — `600`.
Пароль не выводится в логи. Не добавляйте этот файл или `.env` в Git.

Откройте http://localhost:8080 и войдите. Через раздел «Преподаватели»
можно создать аккаунты коллег; пароль показывается однократно.

### Настройки `.env`

| Переменная | Назначение |
| --- | --- |
| `JWT_SECRET` | Случайная строка не короче 32 символов |
| `APP_PORT` | Порт хоста, по умолчанию `8080` |
| `COOKIE_SECURE` | `true` для публичного HTTPS через внешний прокси; `false` для локального HTTP |
| `LOCAL_UID`, `LOCAL_GID` | Владелец файлов на хосте; выставляются init-скриптом |

Внутри контейнера Nginx слушает **только HTTP, порт 80**. TLS не настраивается
и сертификаты не требуются. Внешний прокси должен направлять весь домен на
порт `APP_PORT`, сохраняя единый origin для SPA и `/api/`.
Backend наружу не опубликован. Не выставляйте его напрямую в интернет с
`TRUST_NGINX=true`: заголовок `X-Real-IP` должен перезаписываться Nginx.
Ограничение входа — 20 попыток за 5 минут на адрес Nginx; за внешним прокси
оно может применяться к адресу прокси. Для production настройте дополнительный
rate limit на внешнем прокси по реальному IP клиента.

Все данные сохраняются в `./data/ututor.db`; учётные данные — в
`./.admin_credentials`. Остановка `docker compose down` их не удаляет.
Для резервного копирования остановите backend и скопируйте `data/` либо
используйте SQLite backup API. Не копируйте один `.db` без WAL при работающем сервере.

```sh
docker compose logs --follow backend
docker compose up --build -d
docker compose down
```

## Локальная разработка

Python 3.12 и Node 22+ с pnpm 10.12.1:

```sh
python3.12 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements-dev.txt
export JWT_SECRET="$(openssl rand -hex 32)"
backend/.venv/bin/uvicorn app.main:app --app-dir backend --reload --port 8000
```

При запуске из корня БД создаётся в `data/`, начальный пароль — в
`.admin_credentials`. В другом терминале:

```sh
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend dev
```

Откройте http://localhost:5173. Vite проксирует `/api` на `127.0.0.1:8000`.
Публичной регистрации и демонстрационного пароля нет.

## Рабочий сценарий

1. В базе выберите категорию, создайте папку класса и список.
2. Добавьте задания в визуальном конструкторе, вставьте размеченный текст
   в Raw или загрузите UTF-8 `.txt` перетаскиванием.
3. Проверьте отмеченные ударения. Непроверенные задания недоступны для тренировки.
4. Создайте ученика или группу в «Учебных профилях» и прикрепите списки.
5. Откройте список или отметьте несколько списков одного раздела и нажмите
   «Общая тренировка». Отметьте задания. «С ошибками», «Новые» и случайный
   выбор **добавляют** элементы к текущему выделению.
6. Пройдите тренировку. Порядок заданий и вариантов перемешивается сервером.
   После ответа нажмите «Дальше», Enter или Пробел.
7. Посмотрите результат, отработайте ошибки или вернитесь в профиль.

Первый ответ по каждому пропуску фиксируется на сервере. Верным считается
только задание без единой ошибки. Новый успешный раунд меняет ошибочный статус
на изученный. Незавершённое задание в статистику не попадает.
Кнопка «Завершить тренировку» предлагает два варианта:

- «Завершить полностью» — показать итог только по завершённым заданиям;
  частично отвеченное слово и нерешённые задания не учитываются.
- «Сохранить и выйти» — вернуться в профиль и позже продолжить с того же
  задания, включая ответы внутри слова. Сохраняются порядок слов и вариантов.

Тренировка хранится на сервере и восстанавливается после перезагрузки страницы.
Незавершённая тренировка блокирует новую только по участвующим в ней спискам
в том же учебном профиле. Другие списки доступны, в том числе в том же разделе.
В профиле могут храниться несколько тренировок по непересекающимся спискам.
Для нужной тренировки нажмите «Продолжить / завершить» и либо допройдите её,
либо завершите полностью. Общая тренировка блокирует каждый из её списков.
Статистика объединённой тренировки учитывается в исходном списке каждого слова.
Возврат в профиль открывает раздел только что выполненной тренировки.

Редактирование списка сохраняет идентификаторы и прогресс **неизменённых строк**.
Изменение текста или ответа создаёт новое задание с чистым прогрессом.
Открепление списка не удаляет прогресс; удаление списка или папки — удаляет.

## Форматы импорта

Первая альтернатива всегда правильная. Максимум 1 МБ и 3000 заданий в списке.
Пустые строки пропускаются; некорректная строка блокирует импорт с номером ошибки.
Текстовый редактор показывает номера физических строк, включая пустые.
В текстовом режиме и при импорте есть кнопка «Скопировать промт» — инструкции
для нейросети с правилами и примерами именно выбранного типа задания.

В любом месте задания можно добавить пояснение в квадратных скобках.
Например, `[песочный] зАмок`, `замОк [дверной]` или `зА[песочный]мок`.
Пояснений может быть несколько; пустые и вложенные скобки не допускаются.
Исходное расположение сохраняется в сыром тексте. В визуальном редакторе для
этого есть отдельное поле «Пояснение / контекст». Пояснение видно при выборе
слов и над заданием в тренировке, но оно не является частью ответа.

### Орфоэпия

```text
Дерево
собАка
каталОг
[песочный] зАмок
[дверной] замОк
замок
```

Ударения автоматически определяет `russian_g2p` по словарю словоформ.
Библиотека и её данные устанавливаются вместе с backend; при импорте списков
интернет не нужен, обращения к Викисловарю отключены. Неизвестные слова и
неоднозначные ударения требуют ручного выбора ударной гласной в редакторе
(«Требует проверки»); до исправления они недоступны для тренировки.
Словарь не гарантирует полного покрытия омографов; известные пропуски
перечислены как требующие проверки в `backend/app/stress.py`.
Явная заглавная гласная задаёт ударение и имеет приоритет над автоматикой;
несколько заглавных гласных — ошибка. Обычное написание с заглавной первой
буквой (`Остановка`) обрабатывается словарём. Для явного ударения на первой
букве используется также знак ударения (`А́рка`); визуальный редактор добавляет
его автоматически. Слова с одной гласной разрешаются автоматически.

### Орфография

```text
Ж(е,и)лезо
Пам(я,и)ть
с(ло,ла)в(о,а,и,е)
мыш(ь,)
опас(,т)ный
грам(,м)ота
По( ,)этому
[значит «потому»] По(, )этому
```

Пустая альтернатива — отсутствие символа (`∅`, кнопка «без символа»).
Вариант из одного пробела — настоящий пробел (`␣`, кнопка «пробел»).
Таким образом, `По( ,)этому` — раздельное написание, `По(, )этому` — слитное.
Не добавляйте пробелы после запятых для оформления вариантов.
После правильного пустого ответа `грам(,м)ота` отображается как `грамота`,
без `∅` и без дополнительного промежутка. В визуальном конструкторе можно
добавлять оба варианта отдельными кнопками; пустое поле ответа означает `∅`,
а поле из одного пробела — `␣`.

При первом запуске обновлённого backend существующие орфографические списки
автоматически переводятся со старого формата (пробел = отсутствие буквы) на
новый (пустая альтернатива). Идентификаторы заданий и их прогресс сохраняются.
Миграция однократная: новые настоящие пробелы в дальнейшем не переписываются.
Старые экспортированные `.txt` перед повторным импортом нужно привести к
новому формату. Старые невозобновляемые сессии отмечаются завершёнными и
не блокируют новые тренировки. Перед обновлением рекомендуется резервная копия БД.

### Грамматические нормы

```text
Установка оборудования для фильтрации воды в будущем (сберечь|сбережет,сберегет,сберечет,сбережгет) здоровье жителей города.
```

Поддерживается несколько пропусков в предложении. Вложенные скобки,
дубликаты вариантов и пустые грамматические ответы не допускаются.

## Проверки

```sh
cd backend
.venv/bin/pytest -q
```

Тесты используют временную SQLite, не затрагивают рабочие данные и проверяют
парсинг, роли, токены, импорт, изоляцию, оценивание и сброс прогресса.

```sh
pnpm --dir frontend test
pnpm --dir frontend build
docker compose build
```

Frontend-тесты проверяют аддитивный случайный выбор, исключение непроверенных
заданий, перемешивание, отображение `∅` и расчёт прогресса.

Структура: `backend/app/` — API и модели, `backend/tests/` — pytest,
`frontend/src/views/` — страницы, `frontend/src/components/` — модальные окна
и конструкторы, `deploy/` — HTTP Nginx и подготовка локального окружения.
